# Diabetic Retinopathy Classification — Model Training & Evaluation

## Overview

This folder contains the Jupyter notebooks used to audit the dataset, train baseline deep learning models, compare their performance, and evaluate the selected model for a five-class Diabetic Retinopathy (DR) classification task.

The project uses retinal fundus images to classify diabetic retinopathy into five severity categories. The experiments were conducted using Python and PyTorch in Kaggle notebooks.

## Folder Structure

```text
training/
├── 01_dataset_audit.ipynb
├── 02_train_baseline.ipynb
├── 03_compare_models.ipynb
├── 04_evaluate_final_model.ipynb
└── README.md
```

## Dataset

The project uses the Diabetic Retinopathy dataset available on Kaggle.

**Dataset source:** [Diabetic Retinopathy — Kaggle](https://www.kaggle.com/datasets/shajinrp/diabetic-retinopathy)

The dataset contains retinal fundus images organized into five classes:

| Label | Class | Description |
| 0 | `No_DR` | No diabetic retinopathy detected |
| 1 | `Mild` | Mild non-proliferative diabetic retinopathy |
| 2 | `Moderate` | Moderate non-proliferative diabetic retinopathy |
| 3 | `Severe` | Severe non-proliferative diabetic retinopathy |
| 4 | `Proliferative_DR` | Proliferative diabetic retinopathy |

The class indices above represent the class order used by the saved model.

### Dataset Audit Summary

The dataset audit identified the following image counts after exact-duplicate handling:

| Class | Unique Images |
|---|---:|
| No_DR | 966 |
| Mild | 526 |
| Moderate | 395 |
| Severe | 575 |
| Proliferative_DR | 996 |
| **Total** | **3,458** |

The initial image inventory contained 3,554 rows. Exact SHA-256 hashing identified 3,458 unique images.

Patient identifiers were not verified. Therefore, image-level duplicate handling does not establish patient-level independence between the training, validation, and test sets.

## Notebooks

### 1. `01_dataset_audit.ipynb`

**Purpose:** Inspect and validate the dataset before model training.

Main tasks:

- Inspect dataset directories and class labels.
- Count images by class.
- Identify missing or unreadable files where applicable.
- Calculate image hashes to detect exact duplicates.
- Examine class imbalance.
- Prepare dataset information for subsequent experiments.

**Output:** Dataset statistics, duplicate analysis, and audit findings.

### 2. `02_train_baseline.ipynb`

**Purpose:** Train and evaluate baseline deep learning models.

The experiments compare three architectures:

- EfficientNet-B0
- ConvNeXt-Tiny
- Swin-Tiny

Main tasks:

- Configure image preprocessing and data loading.
- Train the candidate models.
- Track training and validation metrics.
- Select the best checkpoint according to validation macro-F1.
- Evaluate each model using the existing test split.
- Save checkpoints, training histories, metrics, and predictions.

**Saved artifacts include:**

```text

├── efficientnet_b0_best.pth
├── efficientnet_b0_history.csv
├── efficientnet_b0_test_metrics.csv

├── convnext_tiny_best.pth

├── swin_tiny_best.pth
├── swin_tiny_history.csv
├── swin_tiny_test_metrics.csv

```

The artifacts are generated by the training workflow and may be stored separately from this folder.

### 3. `03_compare_models.ipynb`

**Purpose:** Compare the saved evaluation results from the three candidate architectures.

Main tasks:

- Load saved test metrics and prediction files.
- Compare accuracy, macro-F1, weighted-F1, and quadratic weighted kappa.
- Examine class-level performance.
- Review confusion matrices and prediction errors.
- Identify the strongest candidate based on the recorded metrics.

**Selected model:** ConvNeXt-Tiny.

The selection is based on the saved experimental results. The test split was used during model comparison, so these results should not be interpreted as an untouched final test evaluation.

### 4. `04_evaluate_final_model.ipynb`

**Purpose:** Consolidate the saved results for the selected ConvNeXt-Tiny model.

This notebook uses the saved predictions, metrics, and training history. It does not retrain the model or independently rerun inference.

Main tasks:

- Recalculate test metrics from saved predictions.
- Generate a classification report.
- Plot the confusion matrix.
- Visualize training and validation learning curves.
- Inspect misclassified test images.
- Export final metrics, tables, plots, and a text summary.

**Expected outputs:**

## Important Limitations

- **Existing test split:** The test results were used to compare candidate models. They should not be presented as an untouched final test evaluation.
- **Patient-level independence:** Patient-level separation has not been established because verified patient identifiers were unavailable.
- **External validation:** Performance on an independent external dataset has not been established.
- **Clinical use:** High performance on this dataset does not demonstrate clinical readiness or establish that the model can replace professional assessment.
- **Dataset generalization:** Results may differ on images collected from different populations, cameras, institutions, or acquisition conditions.

The model is intended for research and educational purposes, not standalone medical diagnosis.

## Reproducibility

The saved checkpoints, CSV files, and evaluation plots provide a record of the experiments.

For reproducibility, retain:

- The original dataset and its version.
- The notebook files.
- The model checkpoints.
- The saved predictions and metrics.
- The preprocessing configuration.
- The software environment and relevant random seeds.

Retraining can produce different results if the data split, random seed, dependencies, preprocessing, or training configuration changes.

## Conclusion

This folder documents the dataset audit, baseline model training, architecture comparison, and final evaluation of a five-class diabetic retinopathy classifier.

Among the evaluated candidates, ConvNeXt-Tiny achieved the strongest recorded test metrics and was selected for the final results summary. Further validation on patient-independent and external datasets is needed before drawing conclusions about clinical generalization.
